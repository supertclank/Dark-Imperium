# Advancement through level 3 and Ratling release

Current implementation: `di-phb-1.0-tier1-v3`, adapter `phb-tier1-kotlin-v1`.
Snapshot digest: `5c4d81d1cf9a55be138d5e73a58acfccd96fb2dcb0eeadb157fbcfde08b2a795`.

1. **Advancement API.** Authenticated owner-only GET `/api/characters/{id}/advancement`, POST `/api/characters/{id}/advancement/preview`, POST `/api/characters/{id}/advance`. POST accepts requestId, expectedStateVersion, destinationLevel and newly required choices only. Unknown fields fail deserialization. Readiness and preview do not mutate state. V6 records committed advancement responses.
2. **Advancement UI.** The sheet offers a level-up button only after affirmative server readiness. The panel collects required doctrine, requests an authoritative preview, and requires explicit confirmation. Uncertain failures retain the exact request UUID and body. A 409 refreshes the character. Review can be cancelled before submission; uncertain submissions must be retried or refreshed.
3. **Level 1 → 2.** Certified Human Veteran paths in v2 and v3 advance sequentially using their pinned snapshot. Suppressing Fire is visible but unavailable (PHB-RULE-022). No automatic profile migration.
4. **Level 2 → 3.** Certified Human Veterans select exactly one Regimental Doctrine. Current choices, class, Origin, species and equipment cannot be replaced. Level-down, skips, level 4+, respec, old narrow/v1 advancement, Hive Scum advancement and Ratling higher levels are rejected.
5. **Doctrines.** Shock Trooper, Marksman and Sergeant remain canonical manual features. Conditional attack/damage bonuses are not added to baseline rolls; PHB-RULE-058 remains unresolved. Invalid, missing, foreign and duplicate selections fail canonical validation.
6. **HP and state.** Maximum HP is derived again from the pinned source policy. Current HP is untouched: an example 11/11 becomes 11/18 then 11/25. Resource counters, conditions, temporary effects, inventory UUIDs, quantities, ammunition and equipment flags are retained. Starting kits are not reissued. Constitution changes fail PHB-RULE-014; new/changed resource definitions fail RESOURCE_POLICY_REQUIRED instead of inventing initial uses. Existing certified transitions grant no new resources.
7. **Idempotency and concurrency.** An owner/request advisory transaction lock and character/runtime row locks serialize submissions. Same UUID and payload returns the original stored response, even after later advancement. Changed payload conflicts. Competing UUIDs with one expected version allow only one transition. Forced final-insert failure rolls back level, choices and runtime version. Rename now increments runtime version too.
8. **Ratling species.** PHB PDF 23 supplies +2 Dexterity, +1 Wisdom, Small, 25 ft, Stealth and 60 ft darkvision. Fixed source effects are composed generically for v3. Darkvision uses a dedicated longest-range contract, not a resolution of general stacking. Small Target, Sniper’s Eye, Lucky Shot and Bad in a Straight Fight stay manual. Lucky Shot has a manual one-use/short-rest counter. Human choices and failed-save resource do not leak into Ratlings.
9. **Ratling paths.** Ten level-one families: Veteran and Hive Scum, each with Hiveborn, Penal Worlder, Voidborn, Militarum Regiment and Underhive. Twitchy and reviewed starting kits only. Shrine Worlder remains RARE/approval-blocked. Ratling higher levels remain outside the immutable allowlist. PHB weapon properties (PDF 35), general armour (41–42), and species patterns (44–45) supply no generic Small weapon penalty; none is invented. Heavy weapon strength/training rules are not bypassed: no Heavy weapon is in these starting kits.
