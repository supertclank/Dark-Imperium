# Manual and conditional mechanics

659 manual entries across 659 canonical records are enumerated by owner/local ID/JSON pointer in review/manual-mechanics.json. Each remains structured ManualRule with full text, reason, context and adjudicator; no hidden numeric payload. A keyword-assisted inventory distinguishes potentially GM-adjudicated clauses from mapping backlog, but does not certify an entire mixed record as manual by design. Source ambiguity is tracked in the separate resolution ledger.

Examples of manual-by-design clauses: Heavy movement penalty discretion; target line-of-fire/cover judgement; narrative contacts and relic burdens. Deterministic once-per-rest uses, damage dice, skill benefits and resource costs are implementation backlog, not discretionary merely because currently transcribed. No whole-record readiness is inferred from a manual label.

The sheet, compendium, feature lists and GM tools must display retained manual text, usage and unresolved status. It contributes nothing automatically. A human adjudication is a separate state change with provenance; manually retained text must never be interpreted as code.

Conditional encoding added: Riot Shield subclass level3 grants +1 defence only while a shield is equipped. Its separate shove-advantage clause remains visible manual text. Missing equipment context returns unresolved. Armour Familiarity still needs proficient-armour and non-critical-hit context; leave it manual. Aeldari Grace needs authoritative light/Aeldari armour taxonomy. Bloodied uses <=half; Ruststalker and similar below-half clauses use strict<. Once-per-rest is a resource, not a health/equipment predicate; resource/action mapping is still required.

Review/canonical-coverage.json covers every canonical record. STRUCTURED_SUBSET describes supported field validation, not source completeness or publication readiness. Unknown conditions never silently apply a bonus.
