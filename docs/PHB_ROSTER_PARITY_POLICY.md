# PHB roster parity policy

No currently published class may be certified beyond Level 5 until every mechanically viable core PHB class has reached Level 5, or has an explicit documented content, rule, engine or approval blocker.

This is a development/certification policy, not a player-facing game rule. It does not itself authorise Level 6 work. Preserve historical profile bytes and stable class IDs. A newly published path must support continuous creation at 1 and advancement through 2, 3, 4 and 5. Unavailable mandatory choices may not be hidden behind a nominal class publication.

The authoritative implementation inventory is [class-roster-level5-audit.json](../content/packages/di_phb_1_0/review/class-roster-level5-audit.json), generated by `python tools/audit_class_roster_level5.py`. Class completion is mutually exclusive: certified paths through all five levels, or explicitly blocked. Certified classes can retain individually blocked subclass/equipment alternatives; these must be listed separately and excluded from selection. The matrix covers all 12 source classes and all 45 subclasses, with source pages, canonical training, progression, equipment, resources, restrictions and blockers.

Manual conditional effects are acceptable and use shared presentation. Missing game rules are not equivalent to unautomated rules: do not invent an undefined save outcome, terrain duration, stacking rule or approval. A mandatory incomplete kit can block publication even where ordinary attacks and class HP work.
