# Character Builder presentation and ability-score UX

Completed 23 October 2026 against the existing v4 release. This is a presentation/API metadata change; no game-design decisions or new catalogue paths were introduced.

1. **Species UI.** Shared selectable archive cards show canonical summaries, ability adjustments/choices, size, speed and vision. Human's distinct ability choice is derived from valid choice grants. Expandable sections separate individual source traits and distinguish classes with supported paths from canonical classes coming later. Existing eligibility filtering remains authoritative.
2. **Origin UI.** Cards separate flavour, approved NORMAL/RARE/LIMITED species labels, chosen skills, fixed additional proficiencies and individual benefits. RARE/LIMITED explicitly require GM approval; these badges do not make those combinations selectable or approve them.
3. **Class UI.** Cards group hit die, primary abilities, saves, armour and weapon training, plus progression restricted to levels certified for the selected species/origin/class. Existing feature-support classifications and player notes are retained, including unavailable Suppressing Fire.
4. **Subclass UI.** The generic selected-detail component immediately displays pinned subclass feature text, relevant levels and calculation/manual/unavailable annotations. It works in creation and advancement; changing doctrine replaces the previous detail. No doctrine names or feature mechanics are hard-coded in React.
5. **Standard Array.** All six base scores begin unassigned. Every selector always retains the dash/Unassigned option. Assigned values disappear from other selectors but remain in their own. Clearing returns a score; changing to an unused score releases the old one and never swaps another ability. Existing exact-array server validation rejects duplicate, missing, extra and non-array input.
6. **Ability layout.** Base, species adjustment, final score and modifier are separate columns. Species choices have a separate section. Final values and score-floor explanations come from traces of the existing backend calculation, including the before/after values and minimum. Adjustment explanations also appear in review/saved sheets. Incomplete allocations show instructions rather than guessed final scores.
7. **Accessibility.** Native labelled radio inputs retain keyboard semantics. Selection is expressed by the radio, explicit Selected text and border; focus has a visible outline. Disclosures are independent interactive controls. Base selects have accessible ability labels and an Unassigned option; subclass and available-pool updates use polite announcements. Navigation retains heading focus and validation feedback.
8. **Responsive behaviour.** Card columns adapt to available width. Below 600px, each ability label occupies a full row and the four values have individual column labels. Text wraps and controls retain touch-sized targets. Desktop screenshots were inspected. The available browser tab API exposes no viewport-resize capability, so a true narrow/mobile browser acceptance run remains unverified.
9. **Frontend tests.** 63 passing (all 56 existing tests retained and seven new cases). Existing creation helpers now explicitly allocate the array and assert the submitted allocation. New tests cover initial emptiness, reservation/release, no swapping, whole-card/disclosure behaviour, doctrine switching, backend floor display and fallback trait text. TypeScript passes.
10. **Backend regressions.** 77 passing, zero failures/errors/skips, against native local PostgreSQL. Three new tests cover forged arrays, preview/review score-floor consistency, and canonical presentation/rarity/doctrine data. Existing persistence, advancement, dice, history, idempotency, ownership, consumable and transaction coverage remains passing. `installDist` succeeds.
11. **Content regressions.** All 141 content tests pass. Canonical content, eligibility, prepared-only content and unresolved rulings are unchanged.
12. **Browser acceptance.** Expanded Human and Ogryn traits, selected Ogryn by clicking its descriptive card surface, returned to Human, checked Hiveborn/Militarum NORMAL/RARE/LIMITED labels, verified score reservation and release, completed the full array and species bonus, inspected Veteran levels 1–3, selected Marksman then Sergeant and observed immediate detail replacement. Saved level-3 **Lucan Archive UX** (`81b0de15-7477-4da3-96fb-41ca19f94c2c`). Initiative and confirmed grenade damage worked with the 3D tray; grenade inventory decreased from two to one. Reload retained the character, doctrine, both history records and inventory. Reopened narrow-profile Cassian and v2 Ferrus; reviewed Ferrus's level-2→3 Marksman advancement with correct pinned profile and preserved current HP, then cancelled without changing that historical character. Earlier profile and advancement commits are additionally covered by the backend suite. Browser inspection found and fixed a prose-colon segmentation bug, inherited stat-layout styling and duplicate Origin group keys.
13. **Production build.** Next.js production compilation, TypeScript and all eight static pages succeed. Final standalone traced-file packaging still fails with Windows EPERM while creating dependency directories in the isolated build workspace. A deployable standalone frontend package is not verified. Backend distribution succeeds. Docker startup remains unverified as previously authorized; this pass used native PostgreSQL.
14. **Snapshots.** No snapshot or canonical data file changed; no v5 release exists. Current profile remains `di-phb-1.0-tier1-v4`, adapter `phb-tier1-kotlin-v1`, digest `2ef85cd454999670ee61f51eebcc9b23e6805d5220b518d2c5643001831c5119`. All older profiles remain pinned. New presentation fields are derived at response time; score traces do not change formulas.
15. **Known UI limitations.** Species/Origin source paragraphs are segmented only for display; this parser does not determine mechanics. Canonical prose can remain lengthy when expanded. Species final-score previews require a complete valid base array and the required species bonus choices. Supported-path badges indicate that at least one certified path exists; actual choices still depend on the selected Origin and level. Mobile browser verification and standalone packaging remain outstanding environmental checks.

## Reproduction

- Content: `python -B -X utf8 -m unittest discover -s tests/content`
- Frontend: `node node_modules/vitest/vitest.mjs run` and `node node_modules/typescript/bin/tsc --noEmit` from frontend. On this Windows sandbox, TEMP/TMP point to the writable workspace test-temp directory.
- Backend: Gradle `test installDist --offline --no-daemon` with JDK 21 and TEST_DATABASE_URL pointing at the existing isolated `imperium_nonhuman_final_test` database.
- Frontend production: unchanged Next standalone configuration, using an isolated copy outside OneDrive; final packaging limitation recorded above.
