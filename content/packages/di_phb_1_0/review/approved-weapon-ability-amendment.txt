## 15. Approved PHB-RULE-024 Amendment

Update the existing PHB-RULE-024 weapon ability policy.

The previous Finesse policy allowed choosing Strength or Dexterity.

That portion is superseded.

The new policy is:

### Standard melee weapons

Use:

```text
Strength
```

for attack and damage.

### Finesse melee weapons

Use:

```text
Dexterity
```

for attack and damage.

There is no player Strength/Dexterity choice.

### Ranged weapons

Use:

```text
Dexterity
```

for attack and damage unless explicitly overridden.

### Thrown weapons

Use the weapon's normal fixed attack ability.

Examples:

- Thrown Knife → Dexterity
- a thrown Strength-based melee weapon → Strength unless canonical weapon data explicitly says otherwise

### Psychic/Special Weapons

An explicit feature/weapon override takes precedence.

Example:

- Spirit Weapon may use the explicitly defined psychic ability if the canonical rule grants that substitution.

### Save-Based Damage

Save-based attacks do not automatically add an ability modifier unless their canonical rule explicitly says so.

### Explicit Overrides

Specific weapon/feature text always beats the generic category rule.

## 17. Server-Resolved Ability

Every executable weapon action should expose its resolved ability through calculated action metadata.

Conceptually:

```text
attackAbilityId = dexterity
damageAbilityId = dexterity
```

or:

```text
attackAbilityId = strength
damageAbilityId = strength
```

React displays the resulting modifier.

React does not decide which ability makes sense.

---

## 18. No Weapon-Specific React Branches

Forbidden:

```ts
if (weapon.name === "Knife") {
  ability = "dexterity"
}
```

Forbidden:

```ts
if (weapon.name.includes("Hammer")) {
  ability = "strength"
}
```

The rule/content engine resolves this from structured canonical properties/effects.

## 19. Generic Weapon Metadata

Where necessary, extend canonical weapon/action metadata with a declarative binding such as:

```text
attackAbilityPolicy:
  DEXTERITY
```

or:

```text
attackAbilityPolicy:
  STRENGTH
```

or:

```text
attackAbilityPolicy:
  EXPLICIT_OVERRIDE
```

Exact schema naming should fit the existing architecture.

Do not encode game logic in display strings.

## 20. Finesse Semantics

Finesse now means:

```text
this weapon uses Dexterity
```

for the ordinary Dark Imperium weapon-action calculation.

It no longer means:

```text
player chooses Strength or Dexterity each attack
```
