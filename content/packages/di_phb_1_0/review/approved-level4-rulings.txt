# Approved PHB-RULE-014

## Constitution Modifier and Maximum HP

When a character's Constitution modifier changes, maximum HP is recalculated retroactively.

Each character level receives the character's current Constitution modifier once.

If the Constitution modifier changes from `oldModifier` to `newModifier`:

```text
maximumHpDelta =
(newModifier - oldModifier) × characterLevel
```

This applies to all levels already attained.

## Minimum Hit Point Contribution

For each class level:

```text
classHitPointContribution =
max(1, hitDieContribution + constitutionModifier)
```

At level 1, the Hit Die contribution is the maximum class Hit Die value.

At later levels, use the existing recorded/fixed Hit Die contribution.

Species and class features that separately add maximum HP are applied outside this minimum.

Example:

Ogryn Massive Build remains an additional `+3 HP per level`.

It is not part of the minimum-one calculation.

## Current HP

Increasing maximum HP due to Constitution does **not** restore current HP.

Example:

```text
Current: 11 / 25
New maximum: 29

Result:
11 / 29
```

If maximum HP decreases below current HP:

```text
currentHp = newMaximumHp
```

No other healing or damage occurs.

## Historical HP

If rolled level HP is supported in future, preserve the historical Hit Die roll.

Only the Constitution contribution is recalculated.

Mark PHB-RULE-014 RESOLVED.

# Approved PHB-RULE-015

## Ability Score Improvement

At a class level that grants:

`Ability Score Improvement / Talent`

the player chooses exactly one of:

### Option A

Increase one ability score by:

`+2`

### Option B

Increase two **different** ability scores by:

`+1 each`

### Option C

Choose one eligible Talent instead.

These options are mutually exclusive for that advancement event.

## ASI Maximum

An Ability Score Improvement cannot increase an ability score above:

`20`

This is an **ASI-specific limit**.

It does not create a universal ability-score maximum.

Features with their own explicit maximum/minimum continue to use their own text.

The existing PHB-RULE-009 policy remains intact.

## No Wasted Increase

The complete selected increase must be legal.

Examples:

```text
18 → 20 using +2
VALID
```

```text
19 → 21 using +2
INVALID
```

```text
19 → 20 and another ability +1
VALID
```

```text
20 → 21
INVALID
```

Do not silently reduce +2 to +1.

Do not allow intentionally wasted ASI points.

Mark PHB-RULE-015 RESOLVED.

# Approved PHB-RULE-016

## Repeated Talents

A Talent may be selected only once per character unless that Talent explicitly states that it may be selected more than once.

The current PHB Talent catalogue does not establish a general repeatability rule.

Therefore:

- General Talent: maximum once
- Species-restricted Talent: maximum once
- Class/species requirements must be satisfied
- Future Talent with explicit repeatability text may override this rule

A character receiving another ASI/Talent opportunity may choose:

- an ASI
- a different eligible Talent

but may not select an already-owned non-repeatable Talent.

Universal Traits are separate from Talents.

Universal Trait ownership does not prevent a similarly themed Talent unless a specific prerequisite says otherwise.

Mark PHB-RULE-016 RESOLVED.
